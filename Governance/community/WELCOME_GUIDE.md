Welcome. This guide is the shortest path from "I just found this project" to "my
first pull request is open". It assumes no prior knowledge of the codebase.

## 1. Your first steps

1. **Read the ground rules.** [`CODE_OF_CONDUCT.md`](../CODE_OF_CONDUCT.md) and
   [`CONTRIBUTING.md`](../../CONTRIBUTING.md) — the latter is authoritative for
   branching, commits, the PR checklist, and review expectations.
2. **Get the project running.** Follow the setup instructions in the
   [`README.md`](../../README.md). If a step is broken, that is a useful bug
   report — open an issue.
3. **Pick a first issue.** Look for the labels for newcomers, described in
   [`policies/GOOD_FIRST_ISSUE.md`](GOOD_FIRST_ISSUE.md) and
   [`policies/FIRST_TIME_CONTRIBUTOR.md`](FIRST_TIME_CONTRIBUTOR.md). Comment on
   the issue to say you are taking it, so two people do not duplicate work.
4. **Open a draft pull request early.** A draft PR that links the issue lets a
   maintainer course-correct before you finish, which is faster for everyone.
5. **Ask for a mentor if you want one.** See
   [`community/MENTORSHIP_PROGRAM.md`](MENTORSHIP_PROGRAM.md).

## 3. Where to get help

- **General questions:** the [Telegram community](https://t.me/teachlinkOD) or
  GitHub Discussions — see
  [`policies/COMMUNICATION_NORMS.md`](../policies/COMMUNICATION_NORMS.md) §3.
- **Task-specific questions:** comment on the issue you are working on, so the
  answer is recorded for the next person.
- **Stuck on setup or CI:** open an issue and quote the exact error; include the
  command and the platform.
- **Security or privacy concerns:** **never** post publicly — use the private
  channel in [`SECURITY_POLICY.md`](../SECURITY_POLICY.md).
- **A conduct problem:** contact a maintainer privately as described in
  [`CODE_OF_CONDUCT.md`](../CODE_OF_CONDUCT.md).

No question is too basic. If something in this guide or the setup was unclear,
saying so improves the project for the next newcomer.

## 4. What good looks like

- One issue, one focused change, one pull request.
- Commits that follow [`CONTRIBUTING.md`](../../CONTRIBUTING.md), signed off per
  [`policies/DCO.md`](../policies/DCO.md).
- A pull request that links its issue and explains what changed and how it was
  verified.
- Polite, specific review on both sides, per
  [`community/REVIEW_ETIQUETTE.md`](REVIEW_ETIQUETTE.md).
