## 1. Review frequency

- **Quarterly roadmap reviews**: Full review of the roadmap at the start of
  each quarter.
- **Mid-quarter check-in**: Brief progress check halfway through each quarter.
- **Ad-hoc reviews**: Called when a major event affects the roadmap (e.g. new
  dependency, security incident, community feedback).

## 2. Inputs and participants

| Input | Source |
| --- | --- |
| Issue backlog | GitHub Issues |
| Community feedback | Discussions, surveys |
| Contributor proposals | Open issues and PRs |
| Previous roadmap progress | Last roadmap review document |

Participants:

- Project lead (facilitator)
- Maintainer Team
- Contributors (invited to provide input)

## 3. How changes are approved

- Roadmap changes are proposed as a PR to the roadmap document.
- Changes require Maintainer Team approval.
- Major direction changes require project lead approval.
- Approved changes are documented in the Decision Log.
